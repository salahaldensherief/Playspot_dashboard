# Owner-controlled staff permissions — 25 October 2026

Status: Draft, targeting `dev`. This Dashboard change depends on Mobile/backend Draft PR #85. Neither change has been merged or deployed.

The existing Dashboard edits lounge-wide role templates but has no per-employee control. The existing exact-schema backend permits direct manager writes to permission overrides, so hiding a switch would not fix self-escalation. Backend PR #85 supplies an owner-only `set_staff_permission` RPC, a branch-scoped `get_lounge_staff_permissions` read and a protected audit trail. This Dashboard branch adds a separate employee-permission dialog to the existing staff detail view, visible only to an owner/super-admin for another non-owner employee. It reads effective permissions for the selected lounge, sends changes through the new RPC, accepts only a response matching lounge, employee, permission and value, and reloads server state after success. Errors leave the existing value visible. Arabic and English copy is included; no broader Dashboard design changed.
