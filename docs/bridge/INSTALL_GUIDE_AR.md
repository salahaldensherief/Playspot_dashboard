# دليل ربط PlaySpot بنظام الصالة — نسخة تجريبية للمراجعة

> **حالة الميزة:** أسئلة تقييم وخطة تجهيز فقط. **لا يوجد برنامج Local Agent قابل للتثبيت أو API Connector مُفعّل حتى الآن.** لا تستخدم الدليل لتجربة حجز على عميل حقيقي. الإجابات حاليًا تحفظ محليًا في مسودة المتصفح ولا تُرسل لفريق التكامل.

## مين المفروض يعمل إيه؟

- **صاحب الصالة:** يوافق على الربط ويحدد نوع البرنامج ويستأذن الشركة المورّدة.
- **الموظف:** يجاوب الأسئلة بمعلومات متأكد منها؛ لو مش عارف يختار «مش عارف».
- **فريق PlaySpot:** يتحقق من أمان التكامل، يعمل خريطة الأجهزة، يختبر المزامنة ويوافق على التشغيل.
- **شركة البرنامج القديم:** تؤكد إمكانيات API أو التكامل المحلي والتراخيص والقيود.

## الخطوة 1: اعرف البرنامج اللي عندك

1. افتح الكمبيوتر اللي بتدير عليه الصالة.
2. بص لاسم البرنامج أعلى النافذة، أو افتح **Help > About** لو الخيار موجود.
3. اكتب اسم البرنامج ورقم الإصدار على ورقة. مش لازم تفتح أي إعدادات متقدمة.
4. اسأل صاحب الصالة: هل النظام شغال على موقع في الإنترنت (Cloud)، ولا برنامج على جهاز Windows داخل الصالة؟
5. اسأل المورد هل فيه **API موثّقة** أو **وسيلة تكامل محلية رسمية**. ما تحاولش تفتح أو تعدل قاعدة بيانات البرنامج بنفسك.

## الخطوة 2: املأ أسئلة PlaySpot

1. في إعداد الصالة، خلّص معلومات الصالة، الرومز، الأسعار، الدفع والمستندات كالمعتاد.
2. هتلاقي خطوة «ربط نظام إدارة الصالة» قبل المراجعة النهائية.
3. اختار **مفيش برنامج** لو هتشتغل على إدارة PlaySpot فقط.
4. اختار **نظام أونلاين** لو عندك خدمة Cloud، أو **Windows** لو البرنامج على كمبيوتر داخل الصالة.
5. اكتب اسم وإصدار البرنامج؛ متكتبش أي كلمات سر أو مفاتيح API.
6. جاوب «أيوه / لا / مش عارف» على السماح بالربط، وجود API، الوصول من الإنترنت، قراءة الإشغال، حجز المواعيد المستقبلية، والتحكم في الجلسات.
7. اقرأ «الخطة المقترحة». كل حاجة تحت «لازم نتأكد» هي نقطة ناقصة، **مش خطأ عملته**.
8. كمل تسجيل الصالة عادي. **الاستبيان ليس طلب تركيب رسميًا بعد**؛ تحتاج قناة تسليم معتمدة في الإصدار القادم.

## الخطوة 3A: لو عندك API على الإنترنت

**ده إجراء مخطط للفريق الفني — مش متاح لصاحب الصالة من داخل PlaySpot حاليًا.**

1. اطلب من شركة البرنامج رابط توثيق الـ API وبيئة **Sandbox**.
2. اطلب قائمة العمليات المدعومة: عرض الأجهزة، الإشغال، إنشاء/إلغاء حجز، بدء/تمديد/إنهاء جلسة.
3. فريق PlaySpot يختبر قراءة البيانات في الـ Sandbox أولًا؛ ثم يختبر حجزين في نفس اللحظة.
4. ما تقبلش الحجز الفوري لمجرد أن الـ API بتقول «متاح». لازم النظام القديم يخصص الفترة ويمنع التعارض بشكل ذري.
5. فريق التكامل يجهز ربط OAuth أو بيانات الدخول الخاصة بالخادم في خزنة أسرار مخصصة؛ **مش في استبيان التسجيل، ومش في Flutter**.
6. بعد الاختبار، يتم مطابقة رقم كل روم على PlaySpot مع رقم الجهاز في البرنامج القديم، ومعاينة الأسعار والتوقيت المحلي.
7. يفعّل الفريق التجربة على روم أو اتنين فقط، مع مراقبة الأخطاء وإمكانية إيقاف الربط فورًا.

لو الـ API موجودة **داخل شبكة الصالة فقط**، غالبًا هنحتاج Local Agent للوصول لها؛ مش هنفتح Port عام على الإنترنت.

## الخطوة 3B: لو عندك برنامج محلي على Windows

**الـ Local Agent لسه تحت التصميم، ومفيش ملف تثبيت رسمي منشور. متحمّليش أي ملفات من روابط غير معتمدة.**

1. تأكد إن الكمبيوتر عليه Windows مناسب، وإنه يقدر يفتح مواقع HTTPS.
2. اسأل الشركة الموردة هل تسمح لبرنامج خارجي بقراءة الإشغال وتنفيذ أوامر الجلسات.
3. لازم البرنامج يكون عنده وسيلة تكامل موثقة ومصرّح بيها (API محلية أو SDK أو خدمة موثوقة).
4. **عند إطلاق النسخة الرسمية لاحقًا**: حمّل Agent من صفحة PlaySpot الرسمية فقط، وتأكد من التوقيع الرقمي.
5. هتستخدم كود ربط مؤقت يصدر من PlaySpot، بعد موافقة صاحب الصالة. **كود الربط مش كلمة سر Windows**.
6. Agent يتصل **هو** بالخادم عبر HTTPS مش العكس؛ مش محتاج تفتح IP الصالة على الإنترنت.
7. فريق PlaySpot يختبر حجز تجريبي واحد وجلسة تجريبية واحدة، ويسجل النتيجة.
8. لو الكمبيوتر اتقفل أو الإنترنت فصل: تتحول حالة التزامن إلى «غير مؤكدة»، والحجوزات غير المضمونة تحتاج تأكيد يدوي؛ **ممنوع افتراض التوفر**.

## الخطوة 3C: لو محتاج API + Local Agent (Hybrid)

يمكن قراءة الحجوزات من Cloud API وتنفيذ الجلسات محليًا **لو المورد يتيح الاتنين رسميًا**. فريق التكامل لازم يحدد جهة واحدة مسئولة عن تخصيص وقت الحجز، ويمنع تضارب الأوامر بين القناتين.

## لو مفيش API ولا واجهة تكامل رسمية

- استمر بنظامك الحالي مع **تأكيد يدوي للحجوزات** لو ده مطلوب.
- اسأل شركة البرنامج عن دعم الربط.
- ممكن نعرض عليك PlaySpot OS كحل منفصل، لكن مش هنقول إن التحكم التلقائي في البرنامج القديم متاح.

## جدول المشاكل — حلها ببساطة

| اللي شايفه | غالبًا معناه | تعمل إيه |
| --- | --- | --- |
| «اسم البرنامج أو الإصدار ناقص» | ناقص تعريف النسخة | افتح About واكتب الاسم والإصدار |
| «محتاج موافقة» | الموافقة أو حق التكامل مش واضح | كلم صاحب الصالة والمورّد |
| «وثائق API ناقصة» | مش نقدر نضمن الأوامر المدعومة | اطلب Documentation رسمية |
| «Windows أو HTTPS مش مؤكد» | Agent ممكن ما يقدرش يتصل | راجع الشبكة والكمبيوتر مع الفني |
| «مفيش حجز ذري» | خطر حجزين لنفس الروم | استخدم تأكيد موظف لحد اختبار الحجز |
| «أوامر الجلسات غير مؤكدة» | مش مضمون Start/Extend/End | ما تفعلش التحكم عن بعد |

## ممنوعات أمان مهمة

- ممنوع مشاركة باسورد Windows أو لوحة تحكم البرنامج أو API Key في الاستبيان أو الواتساب.
- ممنوع نشر قاعدة بيانات الصالة أو Port للإنترنت لمجرد تشغيل الربط.
- ممنوع تشغيل Agent غير موقّع، أو استخراج بيانات نظام لا يسمح المورد بدمجه.
- ممنوع إعطاء Local Agent مفتاح Supabase `service_role`.
- ممنوع تفعيل دفع أو جلسة حقيقية قبل اختبار الموافقات ومنع تكرار الأوامر وإمكانية التراجع.

## قبل ما نقول الصالة «متصلة»

يجب نجاح كل البنود: موافقة موثقة؛ هوية صالة؛ خريطة الأجهزة؛ مزامنة الإشغال؛ منع الحجز المزدوج؛ Start/End/Extend لو مدعوم؛ قطع الإنترنت وإعادته؛ صلاحيات الموظفين؛ سجلات تدقيق؛ مراجعة الأسعار والمدفوعات؛ زر إيقاف طوارئ؛ وموافقة فريق PlaySpot.

## حالة التنفيذ الحالية

- ✅ الاستبيان والتقييم والإرشادات داخل مسودة التسجيل موجودة على فرع مراجعة.
- ⛔ لم يتم نشر Connector أو Local Agent، ولم يتم تفعيل API لأي شركة.
- ⛔ إجابات الاستبيان **غير محفوظة على الخادم**؛ تحتاج Backend معتمد وواجهة إرسال محمية مستقبلًا.
- ⛔ لم يتم فحص أي برنامج صالات تجاري بعينه حتى الآن.
