# دليل تركيب Bridge لصاحب صالة الألعاب — بالعربي البسيط

**نسخة تصميم للمراجعة فقط (21 أكتوبر 2026).** مفيش Connector معتمد متاح للتثبيت حاليًا. الخطوات اللي فيها تثبيت أو Pairing هتكون قابلة للتنفيذ بعد تطوير الـ Agent واختباره واعتماد كل Vendor.

## يعني إيه Bridge؟
لو عندك روم اسمها VIP 1 في PlaySpot، ونفس الجهاز اسمه PS-03 في برنامج الكاشير القديم، الـ Bridge يعرف إن الاتنين نفس المكان. يقدر يقرأ حالة الجهاز أو يبعت طلب حجز/جلسة **بس لو البرنامج القديم بيدعم ده فعلًا**.

## الخطوة 1: جهز المعلومات
افتح برنامج الصالة واكتب في ورقة:
1. اسم البرنامج بالضبط (زي ما ظاهر على الشاشة).
2. رقم الإصدار؛ دور على Help أو About.
3. البرنامج على Windows في الصالة، ولا موقع Cloud، ولا جهاز تاني؟
4. أسماء الأجهزة والرومز في البرنامج القديم.
5. رقم الشركة اللي بايعة البرنامج أو رابط موقع الدعم.
6. هل البرنامج يسمح بحجز جهاز لميعاد جاي؟ ولا بيحسب جلسات بدأت بالفعل؟
7. هل صاحب الصالة موافق وشروط البرنامج تسمح بالتكامل؟

مهم جدًا: ممنوع تبعت باسورد Windows، أو API Key، أو كلمة سر قاعدة البيانات، أو بيانات عملاء في الاستبيان أو الشات.

## الخطوة 2: جاوب الأسئلة
الفريق هيعرض استبيان على شاشة تجهيز الصالة (التصميم موجود في questionnaire.v1.json). فيه أسئلة من نوع أيوه/لأ/مش عارف. لو مش عارف اختار مش عارف. الأسئلة التالية تتغير حسب إجابتك.

- معندكش برنامج قديم؟ نرشح PlaySpot OS.
- عندك برنامج Cloud وعنده API رسمية؟ نرشح مسار API.
- عندك برنامج على Windows وله واجهة تكامل محلية مصرح بها؟ نرشح Local Agent.
- الاثنين متاحين؟ نختبر Hybrid: API للحجوزات، وAgent محلي للجلسات.
- مفيش واجهة معلومة؟ نطلب مراجعة الشركة؛ لا نوعدك بحجز فوري.

**الاستبيان لا يفعّل الحجز أو تشغيل الجلسات**، حتى لو كل إجاباتك أيوه.

## الخطوة 3 أ: مسار API الرسمي
API معناها طريقة رسمية نكلم بها برنامجك من بعيد.

1. اطلب من شركة البرنامج رابط توثيق API الرسمي.
2. اسأل هل API بتعرض الأجهزة وأوقات الإشغال والأسعار؟
3. اسأل هل بتستقبل حجز مستقبلي وتمنع حجزين في نفس الساعة بضمان من السيستم؟
4. اسأل هل تسمح ببدء وتمديد وإنهاء جلسة، أم قراءة فقط؟
5. اطلب Sandbox (تجربة) وبيانات عن Authentication وPermissions وRate Limits وWebhooks.
6. ارفع رابط التوثيق فقط، من غير كلمة سر أو Token.
7. بعد موافقة صاحب الصالة، فريق PlaySpot يعمل اتصال قراءة في Sandbox، ويربط معرف كل جهاز.
8. نجرب حجز واحد، إلغاءه، ومحاولة حجزين لنفس الميعاد، وفصل الإنترنت.
9. لو كل الاختبارات نجحت، نعمل Pilot بفرع واحد قبل التفعيل العام.

لو البرنامج يقدر يقرأ الإشغال فقط، ده **مش حجز فوري مضمون**. ممكن نستخدم طلب يحتاج تأكيد موظف.

## الخطوة 3 ب: مسار Local Agent على Windows
Agent يعني برنامج وسيط صغير على كمبيوتر الصالة، لكنه لا يفتح برنامجًا مغلقًا بالقوة.

### تأكد قبل التركيب
1. الكمبيوتر عليه Windows متوافق مع نسخة الـ Agent عند إصدارها.
2. فيه واجهة تكامل محلية رسمية أو مصرح بها من مورد البرنامج.
3. عندك إذن مالك الصالة والشركة أو رخصة الاستخدام المناسبة.
4. الكمبيوتر متصل بالإنترنت وقادر يعمل اتصالات HTTPS خارجية، غالبًا 443.
5. عندك صلاحية تثبيت برنامج على الكمبيوتر بدون مشاركة باسورد الجهاز.
6. عارف أنهي فرع المفروض يترابط.

### خطوات التثبيت المتوقعة عند إطلاق Agent معتمد
1. افتح Dashboard بحساب صاحب الصالة أو مدير مخوّل.
2. اختار الفرع ثم تكامل نظام قديم ثم Local.
3. فريق PlaySpot يتحقق من البرنامج وإصداره والتراخيص.
4. حمّل الـ Agent من رابط رسمي داخل Dashboard فقط. **الرابط غير موجود حاليًا**.
5. تأكد من التوقيع الرقمي واسم الناشر الصحيح.
6. ثبّت بالطريقة المعتمدة، بدون تعطيل Windows Defender أو Firewall وبدون فتح بورت وارد من الإنترنت.
7. اربط الجهاز بالفرع باستخدام كود مؤقت لمرة واحدة يطلع من شاشة آمنة.
8. اختبر اتصال Agent للخارج، وبعده قراءة قائمة الأجهزة من البرنامج القديم.
9. اربط PS-03 بالروم VIP 1، وراجع عدم تكرار الربط.
10. نجرب حجزًا على جهاز غير مستخدم، ومحاولة تعارض، وسيناريو فصل الإنترنت.
11. لو البرنامج يسمح بالأوامر، نجرب Start/Extend/End على جلسة تجريبية فقط.
12. المسؤول يراجع نتيجة Pilot قبل فتح الحجز الفوري.

### مهم للأمان
لا تشارك أسرار في نموذج الأسئلة. تخزين الأسرار لازم يكون في قناة إعداد آمنة ومستقلة بعد مراجعة الصلاحيات. لازم يبقى فيه زر إلغاء ربط (Revoke) وإيقاف Agent. اتصال الـ Agent يكون **خارج من الصالة** فقط، مش سيرفر مفتوح على جهازك.

## الخطوة 3 ج: Hybrid
يمكن API تتولى الحجوزات، وLocal Agent ينفذ أوامر الجلسات لو النظام يدعمها. لازم يبقى فيه مالك واحد للقرار النهائي لكل عملية، وتختبر عدم تناقض البيانات.

## الخطوة 4: اربط الأجهزة بالراحة
مثال:
- PlaySpot Room: VIP 1
- External System: PS-03
- معناها: جهاز واحد له اسمين.

لازم تتأكد إن كل جهاز خارجي مربوط **بروم واحدة فقط** داخل نفس التكامل، وإنه مفيش روم بتشير بالخطأ لجهاز تاني.

## الخطوة 5: حالات الربط
1. Draft: بنجمع الإجابات.
2. Pending review: الفريق بيراجع.
3. Paired: الاتصال الآمن اتعمل.
4. Read only verified: القراءة اشتغلت؛ مفيش حجوزات فورية بعد.
5. Booking pilot: بنجرب الحجوزات.
6. Sessions pilot: بنجرب أوامر الجلسات.
7. Active: بعد اعتماد صاحب الصالة وفريق PlaySpot.
8. Suspended: توقف آمن لو الاتصال أو المطابقة فيها مشكلة.

**لما الاتصال يقطع أو البيانات تبقى قديمة، ما نعرضش حجزًا فوريًا مؤكدًا.**

## الخطوة 6: لما تظهر رسالة خطأ
- Agent Offline: اتأكد الكمبيوتر شغال، والإنترنت والتاريخ والوقت سليمين.
- API Unauthorized: كلم الشركة عن صلاحيات التكامل، من غير إرسال السر لأحد.
- Room not mapped: لازم تراجع الرقم الخارجي ورقم الروم في PlaySpot.
- Booking pending: ما تقولش للعميل الحجز مؤكد؛ دي مرحلة انتظار.
- Command outcome unknown: ممكن الأمر اتنفذ فعلًا والرد ضاع؛ ما تكررش الضغط عمياني.
- Booking conflict: أوقف تفعيل الحجوزات الفورية للفرع، وخلّي الدعم يراجع التعارض.

## قائمة الاختبارات قبل التفعيل
- [ ] موافقة المالك وتصريح الشركة موجودان.
- [ ] الـ API أو الواجهة المحلية مدعومة على إصدار البرنامج.
- [ ] مفيش أسرار أو بيانات عملاء في الاستبيان والسجلات.
- [ ] كل روم مربوطة بالجهاز الخارجي الصحيح.
- [ ] تجربة حجزين لنفس الميعاد لا تؤكد الاثنين.
- [ ] إرسال نفس الطلب مرتين لا يعمل حجزيْن.
- [ ] فصل الإنترنت والرجوع لا يجعلنا نعرض بيانات قديمة كأنها متاحة.
- [ ] Start / Extend / End لا تعمل دون صلاحية أو قدرة مثبتة.
- [ ] موافقة الصالة وفريق PlaySpot على التفعيل محفوظة.

## قاموس صغير جدًا
API = طريقة رسمية برنامج يكلم بها برنامجًا آخر.
Adapter = مترجم خاص بكل نوع سيستم.
Agent = برنامج وسيط محلي.
Mapping = التعريف أن اسم الجهازين هو لنفس الروم.
Atomic booking = البرنامج يخصص الوقت بشكل يمنع حجزين لنفس الموعد.
Idempotency = لو نفس الطلب اتبعت مرتين يتنفذ مرة واحدة.
Webhook = إشعار تلقائي لما حالة الجهاز تتغير.
Reconciliation = مقارنة النظامين بعد انقطاع الاتصال.

**ملحوظة:** بعد تنفيذ أول Adapter معتمد، لازم نوفر صور حقيقية من الخطوات، ورابط تنزيل موقّع، ونظام تشغيل ومواصفات، ومعلومات دعم خاصة بالبرنامج ده. مينفعش نخترعها في الدليل قبل اختبارها.
